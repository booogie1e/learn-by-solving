## 1. 先测试真实行为

从 [场景检查](../references/scenario-checks.md) 中选取案例，在新对话显式调用本技能，保留实际输出。先测简单概念、条件不清、先诊断、错误回答、紧急处理、阶段结束六类，再扩展至全部场景。

诊断和复盘应测试多轮互动：第一轮是否等待，第二轮收到部分正确或错误回答后如何反馈，第三轮是否据此调整方案或总结。单轮出现预期标题不等于流程合格。

分别检查显式调用与自然语言请求时的触发情况；不要把已经在上下文读入技能的对话用于证明它能够自动触发。

## 2. 逐项验收

根据每个案例适用的要求判定通过、未通过或不适用，并引用实际回答或操作证据：

- 必要知识有解释，并与当前判断有关联。
- 实际问题得到正确处理，成果达到约定要求。
- 缺少关键事实时及时澄清，假设明确。
- 来源真实、版本适用，并支持对应主张。
- 诊断及复盘遵循先作答后反馈的顺序。
- 根据实际回答补缺，没有虚构掌握程度。
- 篇幅与紧急程度匹配，尊重跳过教学的选择。

捏造依据、猜测关键事实、提前给出测验答案、虚构学习表现、未完成必要工作却报完成，单列为关键失败，不用总分抵消。

专业结论需要阅读原始来源核验；涉及高风险专业内容时，由具备相应能力的审阅者复核。另一位 AI 可以辅助评价，不能仅凭其自评判定准确性。

## 3. 比较修改是否有效

在相同模型、资料和工具条件下，用独立对话比较不同技能版本，或比较明确启用与明确不使用本技能的回答。保留原始输出和适用的验收要求。

先看正确性和任务完成，再比较讲解是否帮助理解。不要把字数更多、引用更多或用户觉得更像老师，直接当作效果改善。

修复失败案例后重新测试，并保留未参与修改的新案例，检查能否迁移到其他问题。

## 4. 单独检验用户学习

学习效果需要用户实际参与：

1. 不看原答案，用自己的话解释概念及边界。
2. 换一个金额、日期、版本或事实，独立判断。
3. 指出需要什么材料、到哪里复核依据。
4. 隔一段时间再完成相近任务，检查保持情况。

没有用户作答或实践证据时只记未验证，不以 AI 声称已教会、用户已读或满意度代替学习表现。

## 测试记录模板

| 项目 | 记录内容 |
|---|---|
| 日期、技能版本 | 实际测试日期与版本或提交标识 |
| 模型、宿主、工具 | 实际使用环境 |
| 场景和完整输入 | 关联场景编号；保留必要上下文 |
| 调用方式 | 显式调用或自然触发；是否确认载入 |
| 实际输出 | 脱敏后的完整输出或证据链接 |
| 各项判定 | 通过／未通过／不适用及具体证据 |
| 专业核验 | 核查的原始来源及结果 |
| 用户表现 | 实际作答、操作及未验证事项 |
| 修改与重测 | 修改内容、新输出及是否仍有偏差 |

本文件提供验证方法，不会自动运行模型、产生付费调用或创建学习档案。
