# Learn by Solving · 边做边学

**让每次借助 AI 完成工作，都成为一次掌握知识、积累方法的机会。**

A Chinese-first agent skill for learning through real work: essential concepts, actionable answers, authoritative sources, optional diagnosis, and project-based review.

## 为什么做这个技能

AI 可以很快给出答案、方案和成品，但任务完成，并不意味着使用者理解了原理，也不意味着下次能独立处理类似问题。

对刚入职场的人来说，这种差距尤其值得关注：结果交付了，却说不清为什么这样做、依据是什么、换个条件应该怎样判断。

Learn by Solving 把任务处理与学习互动放在同一条流程里。它的目标是让用户在得到帮助的同时，逐步能够解释判断、查找依据并处理新情境。

## 默认怎样工作

**必要知识清单 → 解决实际问题 → 对应权威依据 → 按需诊断补缺 → 项目检验与复盘**

| 环节 | 具体行为 |
|---|---|
| 先给必要知识 | 列出本题所需的背景、概念和方法，用通俗语言解释，并说明各自用在哪里 |
| 继续完成任务 | 给出可执行解答或成果，说明关键事实、适用条件和处理理由 |
| 提供可复核依据 | 优先官方文件、正式标准、原始研究、权威指南，标注相关版本、条款或章节 |
| 及时澄清 | 发现会改变结论的关键事实缺失时询问；非关键缺项明确假设后继续 |
| 诊断与补缺 | 根据用户的解释、判断或操作发现缺口，针对性纠正 |
| 检验与复盘 | 项目完成后，用项目案例和变式提问，反馈后整理可复用方法 |

默认先列知识清单，然后继续解答，**不要求用户先答题才能获得帮助**。

如果用户要求先诊断，则先提少量问题，等待作答后再补缺、形成完整方案。项目测验也先等待回答，再提供解析，避免把练习变成照抄答案。

## 适合谁使用

- 刚入职场、需要熟悉业务和工作方法的新人。
- 转入新领域、希望理解基础知识与实际操作联系的人。
- 希望在使用 AI 时持续积累独立判断能力的专业人员。
- 需要开展项目带教、案例讨论和阶段复盘的团队。

场景可以是法律问题、技术排查、表格分析、业务研究或其他实际工作。专业内容仍需要对应领域的可靠资料和必要复核。

## 安装与使用

### 在 Codex 中使用

1. 下载本仓库，将文件夹命名为 `learn-by-solving`。
2. 把整个文件夹放入个人技能目录 `~/.agents/skills/`，使主文件位于 `~/.agents/skills/learn-by-solving/SKILL.md`。
3. 打开 Codex，显式调用 `$learn-by-solving`。如果列表尚未更新，重新打开 Codex 后查看。

也可以将技能文件夹放在项目的 `.agents/skills/` 下，按项目使用。目录与加载方式见 [Codex 官方技能说明](https://learn.chatgpt.com/docs/build-skills)。

**首次使用示例：**

```text
请使用 $learn-by-solving 处理这个问题：
……
先列出必要知识并继续解答，需要了解我的基础时再做诊断。
```

**用于整个项目：**

```text
这个项目全程使用 $learn-by-solving。
后续追问只补充新的知识或纠正误解；阶段完成后，再做案例检验和复盘。
```

### 三种交互方式

| 方式 | 可以怎样说 |
|---|---|
| 默认：边做边学 | “先列知识清单，再给解答。” |
| 先诊断：回答后出方案 | “先用两三个问题了解我的基础，等我回答再给完整方案。” |
| 紧急处理：教学后移 | “这次先给结果，解释和复盘稍后再做。” |

完成一个阶段后，可以说：“这个阶段结束了，请根据实际内容检查我的理解，再帮我复盘。”

### 其他 AI 工具

核心内容是 Markdown 指令，可供支持相应技能格式或自定义工作流的工具参考。加载路径、调用方式、检索和文件访问能力由宿主工具决定，需分别验证；本仓库没有完成其他工具的兼容性测试。

## 一个问题会怎样被处理

假设用户问：“分期还款前一期没还，下一期还了一笔，逾期天数怎么算？”

技能预期会先解释还款冲抵、应还日和统计日，再检查是否缺少关键规则，随后给出条件明确的计算，并关联适用的依据。

如果项目进入复盘，则可以改变还款金额或冲抵条件，让用户独立判断处理是否变化。

这是**预期交互示意**，不是对特定贷款的专业结论，也不是已经执行的模型测试记录。

## 设计上的几个约束

- **深度跟随任务。** 简单问题短讲，复杂项目按阶段展开。
- **已讲解不等于已掌握。** 根据实际作答或操作记录理解状态，不虚构学习成绩。
- **依据服务于判断。** 说明来源支持什么结论，不只堆链接。
- **保留不确定性。** 无法核实原文时说明范围，不能编造链接、条款或论文。
- **尊重用户选择。** 用户可跳过诊断或测验，工作成果照常交付。
- **不假装长期记忆。** 当前对话之外看不到学习记录时，重新确认起点；需要保存时由用户指定范围和位置。

## 当前状态与验证

首版发布内容为 **v0.1.0**，截至 2026-11-11：

- 技能格式、界面配置和内部引用路径检查通过。
- 已整理 13 个行为验收场景，覆盖诊断等待、关键事实缺失、错误纠正、来源受限、紧急交付和跨领域应用。
- **尚未完成独立模型行为评估。** 场景文档是验收标准，不是通过记录。
- **尚未进行真实学习效果评估。** 不据此宣称本技能能够保证提升能力或减少依赖。

验证方法及可复制的记录表见 [验证说明](docs/VALIDATION.md)。

这是一个指令型技能，没有独立运行程序、内置搜索引擎或自动评分服务。实际执行需要宿主 AI 支持相应能力，回答质量也取决于模型、工具、资料和任务本身。
