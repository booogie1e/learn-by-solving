# 诊断与复盘

仅在用户要求诊断、出现关键误解或进入项目复盘时读取。本文件组织学习互动，不代替专业调查和领域规范。

## 诊断：区分自评和表现

优先利用对话中已有的解释和操作，避免重考。需要新问题时选择关键点：

| 目的 | 适合的问法 | 判断依据 |
|---|---|---|
| 了解起点 | 你接触过哪些环节，最不确定哪一步？ | 仅形成初始假设，不据此认证掌握 |
| 理解概念 | 用自己的话解释A，并说明与B的区别 | 能说明含义及边界，而非复制原句 |
| 判断应用 | 这份项目材料你先核实什么，为什么？ | 能关联事实、依据和行动 |
| 迁移应用 | 只改变条件X，处理会不会变化，还缺什么？ | 能识别前提变化及影响 |
| 自主复核 | 到哪种原始来源、哪个章节验证判断？ | 能独立找依据，不要求记忆链接 |

先诊断模式每轮通常2—3题，提问后暂停依赖诊断的完整方案；随做模式一般一道即可。允许回答不清楚或跳过。不要在题目下面附答案、解析或足以照抄的提示。用户卡住时先给一层提示，明确求答案时再示范。

### 回答后的反馈

1. 指出答对的具体部分。
2. 找到最影响任务的误解或遗漏，区分事实不清与规则理解错误。
3. 用来源、项目证据及短例子修正，说明怎样改变当前行动。
4. 必要时用条件不同的小案例，仅检查刚修正的关键点。
5. 更新知识状态及证据。部分正确记待巩固；未答记未验证。

不做无依据的分数或能力认证。用户要求量化时先说明维度，评价仅限本次表现，不推断职业胜任力。

## 项目收尾：交付与理解分开记录

工作成果可以完成，而学习检验尚未完成。分别说明，不因等待答题扣住可交付成果。

### 先给项目检验题

通常选概念、证据或操作、迁移各一道，按规模增减：

- 本项目最容易混淆的两个概念有什么区别？
- 本项目某项结论由哪份材料和哪项依据支持？
- 改变一个日期、金额、版本或关键事实，原处理是否还适用？

使用脱敏事实，虚构变式明确标为假设。不要引入真实人物完整证件、账户或其他不必要敏感数据。提问后等待；本轮不答可结束答复，用户后续作答时接续，不反复催答。

### 反馈后生成复盘

按实际复杂度组织，不必机械填表：

- 任务与结果：目标、交付、验证范围及未解决事项。
- 关键判断：如何选择、依据是什么、哪个事实改变了方案。
- 知识联系：概念怎样连接操作、证据和结果。
- 理解情况：已能解释、已能应用、待巩固、尚未验证及对应证据。
- 下次独立处理：收集什么、判断顺序、复核方法及需要进一步咨询的节点。
- 精读资料：少量直接针对薄弱点的原始来源，标注阅读位置和应解决的问题。

用户跳过检验时可以直接复盘，只根据已有表现判断理解状态，不为表格完整制造结果。只有用户要求保留时才在指定位置保存脱敏记录，否则留在对话。

## 交互示意

- 开始：本题先掌握这些知识，我会解释用在哪里，然后继续处理。
- 可选诊断：可以试着解释A与B的区别；不影响我先完成目前能确定的部分。
- 先诊断：先用两题了解起点，等你回答再补缺并给完整方案。
- 纠正：A的理解成立，还需条件B。缺少它会影响C，因此先补查D。
- 结束：工作成果已完成，下面用项目情境检查理解，你回答后我再反馈并整理复盘。

这些只示意语气和时序，不要求机械复用。
